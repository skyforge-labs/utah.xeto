# Contributing

Create a branch from `main`, make a focused change, and submit a pull request.
The maintained target is SkySpark/Haxall 4.0.6 with sys/ph 5.0.x. SkySpark 3 fixes
belong on `legacy/skyspark3`; do not merge its old package layout into `main`.

## Setup and checks

Install Java 21+ and Python 3.10+, clone this repository, and run:

```sh
python -m unittest discover -s tests -v
python scripts/build.py
```

The public toolchain is downloaded automatically with checksum verification.
No SkySpark license, credentials, third-party Python packages, or proprietary
Forge extensions are required. CI runs on Windows and Linux.

## Modeling conventions

- Prefix Utah types with `Utah` and use lower-camel-case equipment slot names.
- Reuse sys/ph and `utah` definitions. Cross-domain definitions belong in `utah`.
- Keep domain dependencies one-way: domain → `utah` → standard libraries.
- Distinguish command, feedback, enable, override, and effective setpoint roles.
- Provide a useful description and canonical `navName`; preserve units and
  history policy when changing inheritance.
- Make optional points optional. Require points only when the equipment model
  actually guarantees them. Exercise changes with representative site data.
- Update the library README and migration notes for public namespace, type,
  slot, unit, history, or requiredness changes.

## Pull requests

Describe the equipment or mapping problem, resulting behavior, and validation.
Include a small anonymized example when changing semantics. Never include
customer identifiers, project databases, credentials, or proprietary source.

Build artifacts and downloaded runtimes are ignored. Commit source and docs;
release assets are generated by CI. All six libraries share `utah.version` in
`build.props`; maintainers update it when preparing a release.
